## 하는 일

| 기능 | 내용 |
|---|---|
| 회원 | 이메일 인증 가입, 카카오 로그인, 회원 정보 · 배송지 · 계좌 관리, 판매자 등록, 탈퇴(소프트 삭제) |
| 토큰 발급 | RS256 개인키로 Access · Refresh 발급 (개인키는 member만 가짐), 재발급 · 로그아웃 |
| 토큰 폐기 | 로그아웃 블랙리스트, 탈퇴 · 비밀번호 변경 시 회원 단위 폐기 → [인증 규칙](../conventions/auth.md) |
| 회원 정보 전파 | 회원 · 주소 · 계좌 변경을 이벤트로 발행 → 다른 서비스의 회원 복제본 |

## 정책

세미 프로젝트 정책 문서(`docs/policy.md`, 삭제됨)에서 옮긴 확정 정책입니다.

### 회원가입
1. 회원가입 시 이메일, 비밀번호, 닉네임, 휴대폰 번호, 환급 계좌, 기본 배송지를 반드시 입력한다.
2. 이메일은 인증을 완료해야 가입할 수 있다.
3. 이메일, 닉네임, 휴대폰 번호는 다른 회원과 중복될 수 없다. 계좌 중복 확인은 최종 프로젝트에서 적용한다.

### 이메일 인증
1. 인증번호는 발송 후 5분 동안 유효하다.
2. 인증번호는 60초가 지나야 다시 발송할 수 있다.
3. 인증을 완료한 상태는 30분 동안 유지된다.
4. 인증번호 확인 횟수 제한은 최종 프로젝트에서 적용한다.

### 소셜 로그인
1. 카카오, 네이버 소셜 로그인을 지원한다.
2. 소셜 계정으로 처음 로그인하면 닉네임, 휴대폰 번호, 계좌, 배송지를 추가로 입력해야 가입이 완료된다.
3. 이메일은 소셜 계정에서 받은 값을 사용한다.
4. 같은 이메일로 일반 가입한 회원이 있으면 소셜 가입을 차단하며, 계정을 자동으로 연결하지 않는다.

### 로그인과 토큰
1. 로그인 실패 횟수는 제한하지 않는다.
2. 로그인에 실패하면 이메일과 비밀번호 중 무엇이 틀렸는지 구분하지 않고 안내한다.
3. Access 토큰은 30분, Refresh 토큰은 1일 동안 유효하며, 재발급 시 유효 시간이 새로 시작된다.
4. 로그아웃하면 Refresh 토큰을 폐기하고, 그 Access 토큰은 블랙리스트에 올려 만료 전이라도 거절한다 ([인증 규칙](../conventions/auth.md)).
5. 여러 기기에서 동시에 로그인할 수 있다.

### 권한
1. 권한은 비회원, MEMBER, SELLER, ADMIN으로 구분한다.
    - 비회원: 상품 조회
    - MEMBER: 구매
    - SELLER: 판매와 구매
    - ADMIN: 정산 관리와 전체 기능
2. 상위 권한은 하위 권한의 기능을 모두 사용할 수 있다.

### 판매자와 관리자
1. 로그인한 회원은 누구나 한 번 판매자로 등록할 수 있으며, 등록 즉시 SELLER 권한을 받는다.
2. 판매자 등록 후에는 토큰을 재발급해야 SELLER 권한이 반영된다.
3. 관리자 계정은 일반 회원으로 가입한 뒤 DB에서 권한을 ADMIN으로 변경해 만든다. 가입 API로는 관리자 계정을 만들 수 없다.

### 계좌와 배송지
1. 환급 계좌는 암호화하여 저장한다.
2. 환불, 예치금 환급, 정산금 지급에는 같은 환급 계좌를 사용한다.
3. 계좌를 변경할 때는 비밀번호를 다시 확인한다. 이 정책은 최종 프로젝트에서 적용한다.
4. 회원은 기본 배송지를 1개 가지며, 회원가입 시 저장한다.

### 회원 탈퇴
1. 진행 중인 주문 · 환불, 남은 예치금, 정산 대기 금액이 있으면 탈퇴할 수 없다.
2. 탈퇴는 소프트 삭제로 처리하고 닉네임은 "탈퇴한 회원"으로 바꾼다.
3. 탈퇴하면 그 전에 발급된 토큰을 모두 거절한다 ([인증 규칙](../conventions/auth.md)).
