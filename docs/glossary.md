# 용어집

> 언제 읽나: 코드나 문서의 용어 뜻이 헷갈릴 때
> 상태: ✅ 확정 · 마지막 수정 2026-11-06 · 관련: 전체

## 주문 · 배송

| 용어 | 뜻 |
|---|---|
| `Orders` (주문) | 구매자가 한 번에 결제한 묶음. 여러 판매자의 상품이 섞일 수 있음 |
| `SellerOrder` (판매자 주문) | 주문을 판매자별로 나눈 단위. 배송 · 배송비 · 정산 · 리뷰 · Kafka Key의 기준 |
| `OrdersItem` (주문 상품) | 주문 안의 상품 하나. 취소 · 반품 · 구매 확정 단위 |
| `ACCEPT_PENDING` | 결제 후 판매자 수락을 기다리는 주문상품 상태. 구매자 화면 "판매자 확인 중" |
| `Shipment` (배송) | 판매자 주문 하나의 택배. `READY` → `BOOKED`(화면 "픽업 대기") → `PICKED_UP` → `IN_TRANSIT` → `DELIVERED`, 반품은 방향이 다른 새 행 |
| `CANCEL_PENDING` | 택배사 취소 결과를 기다리는 배송 상태 |
| 반품 | 배송 완료 후 72시간 안, 판매자 귀책만. 판매자 48시간 무응답이면 자동 승인 |
| 자동 구매 확정 | 배송 완료 72시간 뒤 자동 확정 (반품 신청 상품 제외) |

## 돈

| 용어 | 뜻 |
|---|---|
| 충전금 (`charge_balance`) | 토스로 충전한 금액. 계좌로 인출 불가 (탈퇴 정리 때만) |
| 인출 가능 금액 (`withdrawable_balance`) | 정산금. 계좌로 인출 가능 |
| 홀딩 지갑 (`HOLDING`) | 결제된 돈을 정산 전까지 맡아 두는 시스템 지갑 |
| 매출 지갑 (`REVENUE`) | 수수료 · 배송비 · 판매자 부담금이 쌓이는 시스템 지갑 |
| 판매자 부담금 | 반품 배송비 (전부 반품이면 원래 배송비 포함). 정산을 만들 때 차감 |
| 음수 정산 · 미수금 | 부담금이 판매액보다 크면 음수 정산, 회수하지 못한 금액은 미수금 (인출 · 탈퇴 불가) |
| 결과 불명 | 응답 타임아웃으로 상대가 처리했는지 모르는 상태. 바로 보상하지 않고 같은 멱등 키로 확인 |
| `REVIEW_REQUIRED` | 자동 복구를 포기하고 사람 확인이 필요한 상태 |

## MSA

| 용어 | 뜻 |
|---|---|
| 회원 복제본 (`MEMBER_REPLICA`) | 회원 이벤트로 채우는 다른 서비스의 회원 정보 사본 (닉네임 · 권한 · 판매자 여부). 계좌는 복제하지 않음 |
| Outbox | 업무 데이터와 같은 트랜잭션에 저장한 뒤 발행하는 이벤트 표. 유실 방지 |
| DLT | 재시도해도 실패한 메시지가 가는 토픽 |
| 멱등 키 (`Idempotency-Key`) | 같은 요청이 두 번 와도 한 번만 처리하게 하는 키. 업무 ID를 호출하는 쪽이 넘김 |
| 업무 키 | 중복 소비를 막는 데 쓰는 업무 데이터의 유일 값 (정산 UK 등) |
| Saga | 여러 서비스에 걸친 작업을 단계별로 하고, 실패하면 앞 단계를 되돌리는 방식 |
| 이중 검증 | Gateway와 각 서비스가 모두 토큰을 검증 |
| Fail-closed | 확인 조회가 실패하면 허용하지 않고 막는 정책 (탈퇴) |
| SKIP LOCKED · ShedLock | 파드가 여럿일 때 스케줄러 중복 실행을 막는 방법 (행 나눠 가져가기 · 한 인스턴스만 실행) |
| `review_version` | 상품 검수 버전. 수정할 때마다 올라가 오래된 검수 결과를 무시 |
| 이의 신청 | 자동 반려가 틀렸을 때 판매자가 수정 없이 관리자 확인을 요청 |
