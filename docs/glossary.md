# 용어집

> 언제 읽나: 코드나 문서의 용어 뜻이 헷갈릴 때
> 상태: ✅ 확정 · 마지막 수정 2026-11-04 · 관련: 전체

## 주문 · 배송

| 용어 | 뜻 |
|---|---|
| `Orders` (주문) | 구매자가 한 번에 결제한 묶음. 여러 판매자의 상품이 섞일 수 있음 |
| `SellerOrder` (판매자 주문) | 주문을 판매자별로 나눈 단위. 배송 · 배송비 · 정산 · Kafka Key의 기준 |
| `OrdersItem` (주문 상품) | 주문 안의 상품 하나. 취소 · 환불 · 구매 확정 단위 |
| `Shipment` (배송) | 판매자 주문 하나의 택배. `READY` → `BOOKED` → `PICKED_UP` → `IN_TRANSIT` → `DELIVERED` |
| 수거 전 취소 / 반품 환불 | `PICKED_UP` 전이면 취소, 후면 환불 요청 → 판매자 승인 → 반품 |
| 자동 구매 확정 | 배송 완료 72시간 뒤 자동으로 확정 |

## 돈

| 용어 | 뜻 |
|---|---|
| 예치금 | 회원 지갑 잔액. 토스로 충전, 주문 때 차감 |
| 홀딩 지갑 (`HOLDING`) | 결제된 돈을 구매 확정 전까지 맡아 두는 시스템 지갑 |
| 매출 지갑 (`REVENUE`) | 수수료 · 배송비가 쌓이는 시스템 지갑 |
| 정산금 | 판매액에서 수수료 5%를 뺀 금액. 판매자 지갑으로 지급 |
| 결과 불명 | 응답 타임아웃으로 상대가 처리했는지 모르는 상태. 바로 보상하지 않고 같은 멱등 키로 확인 |
| `REVIEW_REQUIRED` | 자동 복구를 포기하고 관리자 확인이 필요한 상태 |

## MSA

| 용어 | 뜻 |
|---|---|
| 회원 복제본 (`MEMBER_REPLICA`) | 회원 이벤트로 채우는 다른 서비스의 회원 정보 사본 (닉네임 · 배송지 · 계좌) |
| Outbox | 업무 데이터와 같은 트랜잭션에 저장한 뒤 발행하는 이벤트 표. 유실 방지 |
| DLT | 재시도해도 실패한 메시지가 가는 토픽 (`{토픽}-dlt`) |
| 멱등 키 (`Idempotency-Key`) | 같은 요청이 두 번 와도 한 번만 처리하게 하는 키. 업무 ID를 씀 |
| 업무 키 | 중복 소비를 막는 데 쓰는 업무 데이터의 유일 값 (정산 UK 등) |
| Saga | 여러 서비스에 걸친 작업을 단계별로 하고, 실패하면 앞 단계를 되돌리는 방식 |
| 이중 검증 | Gateway와 각 서비스가 모두 토큰을 검증 |
| Fail-closed | 확인 조회가 실패하면 허용하지 않고 막는 정책 (탈퇴 · 계좌 변경) |
