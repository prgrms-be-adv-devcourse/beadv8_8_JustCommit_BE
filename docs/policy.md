# 서비스 정책

팀에서 확정한 정책을 정리한 문서입니다. 정책이 바뀌면 이 문서를 함께 수정합니다.

---

## 1. 회원 (Member)

### 1.1 회원가입
1. 회원가입 시 이메일, 비밀번호, 닉네임, 휴대폰 번호, 환급 계좌, 기본 배송지를 반드시 입력한다.
2. 이메일은 인증을 완료해야 가입할 수 있다.
3. 이메일, 닉네임, 휴대폰 번호는 다른 회원과 중복될 수 없다. 계좌 중복 확인은 최종 프로젝트에서 적용한다.

### 1.2 이메일 인증
1. 인증번호는 발송 후 5분 동안 유효하다.
2. 인증번호는 60초가 지나야 다시 발송할 수 있다.
3. 인증을 완료한 상태는 30분 동안 유지된다.
4. 인증번호 확인 횟수 제한은 최종 프로젝트에서 적용한다.

### 1.3 소셜 로그인
1. 카카오, 네이버 소셜 로그인을 지원한다.
2. 소셜 계정으로 처음 로그인하면 닉네임, 휴대폰 번호, 계좌, 배송지를 추가로 입력해야 가입이 완료된다.
3. 이메일은 소셜 계정에서 받은 값을 사용한다.
4. 같은 이메일로 일반 가입한 회원이 있으면 소셜 가입을 차단하며, 계정을 자동으로 연결하지 않는다.

### 1.4 로그인과 토큰
1. 로그인 실패 횟수는 제한하지 않는다.
2. 로그인에 실패하면 이메일과 비밀번호 중 무엇이 틀렸는지 구분하지 않고 안내한다.
3. Access 토큰은 30분, Refresh 토큰은 24시간 동안 유효하며, 재발급 시 유효 시간이 새로 시작된다. Refresh 토큰 유효 시간은 1일로 변경할 예정이다.
4. 로그아웃하면 Refresh 토큰을 폐기한다. 이미 발급된 Access 토큰은 만료될 때까지 유효하다.
5. 여러 기기에서 동시에 로그인할 수 있다.

### 1.5 권한
1. 권한은 비회원, MEMBER, SELLER, ADMIN으로 구분한다.
    - 비회원: 상품 조회
    - MEMBER: 구매
    - SELLER: 판매와 구매
    - ADMIN: 정산 관리와 전체 기능
2. 상위 권한은 하위 권한의 기능을 모두 사용할 수 있다.

### 1.6 판매자와 관리자
1. 로그인한 회원은 누구나 한 번 판매자로 등록할 수 있으며, 등록 즉시 SELLER 권한을 받는다.
2. 판매자 등록 후에는 토큰을 재발급해야 SELLER 권한이 반영된다.
3. 관리자 계정은 일반 회원으로 가입한 뒤 DB에서 권한을 ADMIN으로 변경해 만든다. 가입 API로는 관리자 계정을 만들 수 없다.

### 1.7 계좌와 배송지
1. 환급 계좌는 암호화하여 저장한다.
2. 환불, 예치금 환급, 정산금 지급에는 같은 환급 계좌를 사용한다.
3. 계좌를 변경할 때는 비밀번호를 다시 확인한다. 이 정책은 최종 프로젝트에서 적용한다.
4. 회원은 기본 배송지를 1개 가지며, 회원가입 시 저장한다.

### 1.8 회원 탈퇴
1. 진행 중인 주문, 남은 예치금, 정산 대기 금액이 있으면 탈퇴할 수 없다.
2. 이 정책은 최종 프로젝트에서 적용한다.

## 2. 상품 (Product)

### 2.1 상품 등록
1. 판매자(SELLER)만 상품을 등록할 수 있다.
2. 제목, 설명, 가격, 품종은 반드시 입력한다.
3. 높이, 화분 크기, 성장 메모는 선택 항목이다.
4. 사진은 최소 1장 이상 반드시 등록해야 하며, 최대 10장까지 등록할 수 있다. 첫 번째 사진을 대표 사진으로 사용한다.
5. 판매자 한 명이 등록할 수 있는 상품 수는 제한하지 않는다.
6. 판매 금지 품종으로는 상품을 등록할 수 없다.
7. 농사로 품종 목록에 없는 식물은 "기타" 품종으로 등록한다.

### 2.2 상품 노출
1. 판매 중인 상품은 목록과 상세에 노출한다.
2. 결제 대기 중인 상품은 노출하며 "거래 중"으로 표시한다.
3. 판매 완료된 상품은 노출하며 "판매 완료"로 표시한다.
4. 삭제된 상품은 노출하지 않는다.
5. 숨긴 상품은 판매자 본인 외에는 노출하지 않는다. 판매자 본인은 숨긴 상품의 상세를 조회할 수 있다.
6. 인기순 정렬은 기준 지표(조회수, 찜 수 등)가 필요하므로 최종 프로젝트에서 적용한다. 그 전까지 인기순은 최신순과 같게 동작한다.

### 2.3 상품 수정, 삭제, 숨김
1. 상품은 판매 중일 때만 수정할 수 있으며, 품종을 포함한 모든 항목을 수정할 수 있다.
2. 상품은 판매 중일 때만 삭제할 수 있으며, 삭제된 상품은 데이터를 지우지 않고 삭제 상태로 보관한다.
3. 상품은 삭제된 상태가 아니면(판매 중, 거래 중, 판매 완료) 숨길 수 있다. 숨긴 상품은 새로 주문할 수 없지만, 이미 진행 중인 결제는 그대로 진행한다.

### 2.4 주문 이후
1. 판매자는 자신이 등록한 상품을 구매할 수 없다.
2. 상품은 주문 시점에 거래 중(결제 대기)으로 예약하고, 결제가 완료되면 판매 완료로 처리한다. 결제에 실패해도 결제 대기 시간 동안은 거래 중을 유지하며, 결제 대기 시간이 지나면 다시 판매 중으로 복원한다.
3. 주문한 상품 중 일부만 취소할 수 있으며, 취소된 상품만 다시 판매 중으로 복원한다.
4. 환불된 상품은 다시 판매 중으로 복원한다. 이 정책은 최종 프로젝트에서 적용한다.

## 3. 주문과 배송 (Market)

### 3.1 배송비
1. 배송비는 판매자의 기본 배송지와 구매자 배송지의 거리를 고려해 계산한다.
2. 세미 프로젝트에서는 판매자 주문당 3,000원으로 고정한다.
3. 거리 계산 API는 택배 도메인에서 구현한다.

### 3.2 결제 대기
1. 결제 대기 시간은 10분이다.
2. 예치금이 충분하면 주문과 동시에 바로 결제하고, 부족할 때만 결제 대기 상태로 둔다.
3. 장바구니에서 주문할 때 예치금이 부족하면 먼저 충전한 뒤 주문을 생성한다.
4. 주문 생성 중 예치금이 부족해지는 예외 상황에서는 결제 대기 시간(10분)을 적용해 진행한다.

### 3.3 부분 취소
1. 배송 상태가 배송 준비(`READY`) 또는 접수 완료(`BOOKED`)일 때만 부분 취소할 수 있다.
2. 택배사가 상품을 수거한(`PICKED_UP`) 이후에는 취소할 수 없다.

---

## 4. 결제 (Payment)

1. 예치금은 10,000원 단위로 충전한다.
2. 최소 충전 금액은 10,000원이다.
3. 충전은 취소할 수 없다. 대신 예치금 범위 안에서 인출할 수 있다.

---

## 5. 정산 (Settlement)

1. 정산 수수료율은 5%이다.
2. 수수료는 판매액에만 적용하며 배송비는 제외한다.
3. 수수료 계산에서 원 단위 미만은 버린다.
4. 구매는 배송 완료 시각부터 72시간이 지나면 자동으로 확정된다.
5. 판매자는 정산금으로 다른 상품을 구매할 수 있다.
