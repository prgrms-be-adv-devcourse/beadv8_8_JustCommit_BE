# 0019. 판매자 배송지는 목록 전체를 보내고, 판매자가 수락 때 보내는 주소를 고른다

> 상태: ✅ 확정 · 결정일 2026-11-12 · 결정한 사람: 회원 담당 (팀 합의, 수락 담당과 협의)
> 대체: 0015 (주소 토픽 부분만) · 대체됨: -

## 배경

[ADR 0015](0015-member-topics-two-account-api.md)는 `member.address.events.v1`에 판매자 **기본 배송지만** 보내기로 했습니다. 이 방식이면 판매자는 택배를 항상 기본 배송지에서만 보낼 수 있습니다. 구매자는 주문할 때 배송지를 골라 주문에 복사하는데, 판매자는 보내는 주소를 고를 수 없어 판매자 주소 이벤트를 구현하면서(#233) 다시 정했습니다.

## 결정

`member.address.events.v1`의 `MemberAddressChanged`는 판매자의 **배송지 목록 전체**(바뀐 뒤 전체, 최대 4개)를 암호화해 보냅니다. 판매자 등록 · 배송지 추가 · 기본 배송지 변경 때 판매자만 보내고, 판매자는 주문을 수락할 때 이 목록에서 보내는 주소를 고릅니다(고르지 않으면 기본 배송지). 수락 뒤에 주소를 고쳐도 수락할 때 고른 주소로 보냅니다.

0015 중 **주소 토픽의 내용만** 바뀌고, 회원 토픽 2개 · 계좌를 내부 API로 조회하는 결정은 그대로입니다.

## 고른 이유

- 판매자도 구매자처럼 상황에 맞는 주소(집 · 작업실 등)에서 보낼 수 있습니다.
- 목록 전체를 보내면 받는 쪽은 받은 목록으로 통째로 교체하면 되어, 일부 변경을 맞추는 규칙이 필요 없습니다.
- 배송지는 회원당 최대 4개라 이벤트 크기 부담이 작습니다.

## 다른 안

| 안 | 버린 이유 |
|---|---|
| 기본 배송지만 보냄 (0015) | 판매자가 보내는 주소를 고를 수 없음 |
| 바뀐 배송지 하나씩 보냄 | 추가 · 수정 · 삭제 · 기본 변경마다 받는 쪽 반영 규칙이 달라지고, 이벤트를 놓치면 목록이 어긋남 |

## 영향

- 개인정보: market에 복제되는 판매자 주소가 1개 → 최대 4개로 늘어남. 이름 · 연락처 · 주소는 전송 키로 암호화하고, 배송지 이름(`addressName`)은 보내지 않음
- 순서 · 중복: 배송지를 바꾸는 경로는 회원 행을 먼저 잠그고, 받는 쪽은 `occurredAt`이 더 새로운 이벤트만 반영
