# 0025. 판매자 등록 때 상품 검수 동의를 받고, 동의한 문구 버전과 시각을 기록한다

> 상태: ✅ 확정 · 결정일 2026-11-17 · 결정한 사람: 회원 담당 (검수 데이터 · 운영 설정은 상품 담당과 확인)
> 대체: - · 대체됨: -

## 배경

상품을 등록 · 수정하면 OpenAI Moderation에 상품 사진 · 제목 · 설명을, Anthropic Claude Haiku에 상품 사진을 전송해 검수합니다. 판매자에게 이 전송을 알리고 동의 이력을 남겨야 합니다. 기존 정책은 「사진 외부 전송 · 학습 이용 동의, 내용 · 버전 · 시각 기록」이었는데, 판매자 등록 동의를 구현하면서(#418) 확인해 보니 리플랜트는 상품 사진으로 모델을 학습시키지 않고, 확인한 API 정책과 운영 계정 설정상 검수 데이터는 두 업체의 모델 학습에 사용되지 않습니다(코드 · 콘솔 확인, 2026-11-17).

## 결정

판매자 등록 때 **「상품 검수를 위한 외부 AI 서비스 이용 및 국외 이전」 동의 1개**를 필수로 받습니다. 동의하지 않으면 등록할 수 없고(400), 학습 이용 동의는 받지 않고 문구 안에서 안내합니다.

- 현재 문구 · 버전은 member의 상수(`SellerReviewConsentPolicy`)가 `GET sellers/consent-policy`로 제공합니다. 프론트는 `content`(줄바꿈이 있는 일반 텍스트)를 그대로 보여 주고 문구를 따로 쓰지 않습니다.
- 등록 요청은 화면에 보여 준 버전을 함께 보내고, 현재 버전과 다르면 409 `REVIEW_CONSENT_VERSION_MISMATCH`입니다.
- `SELLER`에는 동의 버전과 서버 시각만 저장합니다(문구 원문 · 동의 여부 칸 없음).
- 문구를 바꾸면 버전을 올리고, 이전 문구 전문은 같은 PR에서 `docs/policies/seller-review-consent/{version}.md`로 옮깁니다. 그 버전으로 실제 동의를 받은 뒤에는 같은 버전의 문구를 고치지 않습니다.

## 고른 이유

- 실제로 일어나지 않는 처리(학습)에 동의를 받지 않습니다.
- 서버가 동의 문구와 버전을 함께 제공하고, 등록 때 요청 버전과 현재 버전이 같은지 확인해 동의 기록의 기준을 하나로 맞춥니다.
- 한 시점의 문구는 한곳(현재는 코드, 지난 것은 docs)에만 있어 어긋나지 않고, 판매자 행마다 원문을 중복 저장하지 않습니다.

## 다른 안

| 안 | 버린 이유 |
|---|---|
| 학습 이용 동의도 함께 받음 (기존 정책) | 일어나지 않는 처리에 동의를 받게 됨 |
| 문구 원문을 판매자 행에 저장 | 같은 문구를 판매자마다 중복 저장. 버전으로 찾을 수 있음 |
| 프론트가 문구를 갖고 서버는 버전만 검사 | 문구와 버전이 두 레포로 나뉘어 함께 바꾸고 함께 배포해야 함 |
| `content`를 Markdown으로 (표 표시) | 프론트에 렌더러 추가가 필요. 표 없이도 읽힘 |

## 영향

- 미해결: 국외 이전에 적용할 법적 근거(동의 또는 법령상 허용 요건)와 필요한 고지 · 공개 항목(이전받는 자 연락처 · 이전 국가 등)은 최종 확인 전. v1은 잠정 문구 → [미정 항목](../open-questions.md)
- 검증: 동의 여부는 HTTP 요청 검증에서 막고, Service는 버전만 확인
- 데이터: V7로 `seller`에 `review_consent_version` · `review_consented_at`(NOT NULL) 추가. 기존 판매자는 운영 전 데이터 초기화로 처리 없음
- 프론트: 정책 조회 → 체크 → 버전과 함께 등록, 409면 다시 조회해 다시 동의
