# 0028. 회원 탈퇴는 본인 재확인 뒤 외부 확인 · 카카오 연결 해제를 잠금 밖에서 하고, 카카오 쪽 연결 해제는 받은 뒤 비동기로 사유별 처리한다

> 상태: ✅ 확정 · 결정일 2026-11-18 · 결정한 사람: 회원 담당
> 대체: - · 대체됨: -

## 배경

탈퇴는 두 곳에서 시작됩니다. 회원이 직접 요청하는 탈퇴와, 회원이 카카오 쪽에서 연결을 끊어 카카오가 알려 오는 연결 해제 웹훅입니다. 기존 문서는 "웹훅이 오면 탈퇴 조건을 확인해 통과하면 자동 탈퇴, 아니면 소셜 연결 해제됨으로 두고 안내"까지만 정했고, 탈퇴 재확인 방식과 연결 해제 회원의 재로그인은 미정이었습니다(#405 · #407 · #422).

정해야 했던 제약은 이렇습니다.

- 탈퇴는 market · payment · settlement 확인과 카카오 연결 해제라는 외부 호출을 거치는데, 이 호출과 member DB 변경을 한 트랜잭션으로 묶을 수 없습니다.
- 카카오는 연결 해제 웹훅에 3초 안에 200으로 응답하라고 요구하고, 웹훅에는 고유 ID · 발생 시각이 없습니다. 서비스가 API로 연결을 끊으면 웹훅을 보내지 않습니다.
- 11/18 로컬 확인: 어드민 키 + 회원번호로 연결을 끊을 수 있고, 이미 끊긴 회원을 다시 끊으면 `-101 NotRegisteredUserException`, 같은 카카오 계정으로 다시 연결해도 회원번호가 같았습니다(테스트한 계정 기준).

## 결정

- **직접 탈퇴**: 본인 재확인(로컬은 현재 비밀번호, 카카오는 이메일 재인증 → 일회용 탈퇴 토큰) → 3곳 탈퇴 가능 여부 확인 → (카카오) 토큰을 꺼낸 뒤 연결 해제 → 최종 회원 잠금 안에서 상태 · 인증 버전을 다시 확인하고 익명화 · 탈퇴 기록 · `MemberWithdrawn` Outbox를 한 트랜잭션으로 저장합니다. 외부 호출 동안에는 회원 잠금을 잡지 않습니다.
- **카카오 해제 뒤 DB 롤백**: 별도 보상 기록 없이 회원은 `ACTIVE`로 남고, 재인증 후 다시 탈퇴할 때 연결 해제의 `-101`을 성공으로 처리합니다.
- **연결 해제 웹훅**: 어드민 키 확인 → 수신 기록 저장 → 3초 안에 200으로 끝내고, 회원 처리는 비동기로 합니다. 처리할 때 카카오에 현재 연결 상태를 다시 물어 재연결 · 늦은 웹훅을 걸러 냅니다.
- **사유별 처리**: 카카오계정 탈퇴 · 강제 탈퇴 · 카카오계정 페이지에서 직접 해제는 자동 탈퇴 대상(3곳이 `ALLOWED`일 때만 탈퇴), 카카오 관리자 처리는 `INACTIVE`만, 가입 미완료 · 회원 없음은 기록만 남깁니다.
- **`INACTIVE`**: 카카오 연결이 끊겼지만 아직 탈퇴하지 않은 상태입니다. 기존 토큰을 폐기(`SOCIAL_UNLINKED`)하고 재발급을 거절하며, 재연결이 허용된 회원은 카카오 로그인으로 `ACTIVE`로 복구합니다.

## 고른 이유

- 토큰만 가진 사람이 추가 확인 없이 탈퇴 · 카카오 연결 해제를 일으키지 못하게 하고, 재확인을 외부 확인보다 먼저 해 외부 호출을 남용하지 못하게 합니다.
- 외부 호출 동안 회원 잠금을 유지하지 않아 같은 회원의 다른 요청(로그인 · 재발급 · 배송지 변경 등)이 불필요하게 대기하지 않도록 합니다. 최종 잠금에서 회원 상태 · 인증 버전을 다시 확인해 탈퇴와 인증 상태 변경 간의 경쟁을 방어합니다. 다만 확인한 뒤 다른 서비스의 상태가 바뀌는 문제는 남습니다.
- 카카오 연결 해제 뒤 DB 롤백이 확인된 경우 회원은 `ACTIVE`로 남습니다. 로컬 테스트에서 재연결 후에도 같은 카카오 회원번호가 유지됐고, 이미 해제된 연결의 `-101`을 성공으로 처리하므로 재인증 후 탈퇴를 다시 시도할 수 있습니다. 이 경로를 위해 별도 보상 기록과 재처리 작업을 두지 않습니다. 커밋 결과 불명(`RESULT_UNKNOWN`)은 자동으로 복구하지 않습니다.
- 3곳 확인은 초 단위가 걸릴 수 있어 웹훅 응답 안에서 끝내면 3초를 넘길 수 있습니다.
- 카카오 관리자 처리는 사용자 의사를 알 수 없는데, 자동 탈퇴하면 개인정보 삭제와 30일 재가입 제한을 되돌릴 수 없습니다.

## 다른 안

| 안 | 버린 이유 |
|---|---|
| 웹훅 요청 안에서 바로 탈퇴 | 3곳 확인 · 회원 잠금 대기로 3초 응답을 넘길 수 있음 |
| 모든 연결 해제 사유를 자동 탈퇴 | 사용자 의사가 불분명한 관리자 처리에도 개인정보 삭제 · 재가입 제한이 걸림 |
| 재확인 · 외부 확인 · 저장을 회원 잠금 하나로 감쌈 | 외부 호출 동안 잠금을 쥐어 다른 요청이 막힘 |
| 카카오 해제 시도를 DB에 먼저 기록하고 보상 작업 | 테이블과 재처리 스케줄러가 늘어남. `-101` 멱등과 회원번호 유지로 재시도만으로 복구 가능 |
| DB 탈퇴를 먼저 커밋하고 카카오 해제는 뒤에 재시도 | 탈퇴는 됐는데 카카오 연결이 남는 상태가 생김. "해제 실패면 탈퇴 막음" 정책과 다름 |

## 영향

- 한계: 확인 후 저장 사이 본인이 충전하면 잔액이 남을 수 있음(기존 한계). 카카오 조회와 DB 잠금은 하나로 묶을 수 없고 웹훅에 발생 시각이 없어 연결 해제 · 재연결 순서를 완벽히 가리지 못함. 폐기와 같은 초에 재연결해 받은 Access는 거절될 수 있음. `-101`은 "연결되지 않은 사용자" 전체를 뜻하므로 회원번호는 DB의 `provider_id`에서만 가져옴
