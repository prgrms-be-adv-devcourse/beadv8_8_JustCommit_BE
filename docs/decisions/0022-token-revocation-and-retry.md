# 0022. 탈퇴 · 비밀번호 변경 시 토큰 폐기와 재처리

> 상태: ✅ 확정 · 결정일 2026-11-15 · 결정한 사람: 회원 담당 (#409)
> 대체: - · 대체됨: - · 보완: [0010](0010-token-revocation-keys.md)

## 배경

[ADR 0010](0010-token-revocation-keys.md)은 탈퇴 · 비밀번호 변경 때 `auth:revoked-member:{memberId}` = 끊은 시각으로 기존 Access를 막기로 정했습니다. 키만으로는 세 가지가 비어 있었습니다.

| 빈 곳 | 생기는 일 |
|---|---|
| 폐기와 겹친 발급 | 로그인 · 재발급이 폐기와 겹치면, 폐기 뒤에 옛 인증 상태로 토큰이 나갈 수 있음 |
| 시각을 읽는 곳 | 발급 시각(`iat`)과 끊은 시각을 서로 다른 서버 시계로 읽으면 순서가 어긋날 수 있음 |
| Redis 기록 실패 | DB 변경은 커밋됐는데 끊은 시각을 기록하지 못하면 기존 Access가 계속 통과 |

## 결정

키 계약(키 · 값 · `iat <= 끊은 시각` 규칙)은 0010 그대로 두고, 발급 순서 · 실패 복구 · 보관 정책을 정합니다.

| 장치 | 내용 |
|---|---|
| 인증 버전 | `member.token_version`. 폐기 때 +1, Refresh 값에 `{memberId}:{인증 버전}`으로 저장해 재발급 때 비교. 옛 인증 버전의 Refresh 삭제를 한 번 시도하고, 삭제에 실패해도 버전 비교로 재발급을 거절 |
| 회원 행 잠금 | 로그인 · 소셜 로그인 · 재발급 · 폐기가 같은 회원 행을 잠금. 대기 제한 3초(설정), 넘으면 409 `MEMBER_BUSY` |
| DB 시각 | Access `iat`와 끊은 시각을 잠금 · 검사 뒤 DB `clock_timestamp()`로 읽음 (초 단위 버림) |
| 폐기 작업 | 회원 변경 · 인증 버전 증가와 같은 트랜잭션에 `MEMBER_TOKEN_REVOCATION` 저장 → 커밋 뒤 Redis 기록 |
| Redis 기록 | Lua 하나로 비교 · 쓰기. 더 이른 끊은 시각으로 덮어쓰지 않고, 같은 끊은 시각이면 긴 보관 기한 유지. 보관 기한 = 끊은 시각 + Access 수명 + 여유 60초(설정) |
| 재처리 | 기본 10초 간격으로 실행하며, 한 번 실행할 때 최대 50건을 한 건씩 `FOR UPDATE SKIP LOCKED`로 확보(다음 시도 시각을 30초 뒤로 미루는 임대)해 처리. Redis 호출은 임대 후 트랜잭션 밖에서 실행. 실패 간격 10초 → 30초 → 1분, 보관 기한까지 재시도 |
| 결과 | `COMPLETED`(Redis 기록 확인 또는 보관 기한 경과) · `PENDING`(커밋됨, 기록 미확인) · 롤백은 예외 · 커밋 결과 불명은 `RevocationOutcomeUnknownException` (호출한 쪽은 자동으로 다시 실행하지 않음) |

Gateway는 Redis에 폐기 시각이 기록된 뒤부터 해당 Access를 거절합니다. `PENDING` 동안에는 기존 Access가 통과할 수 있습니다.

## 고른 이유

- 발급이 회원 행 잠금을 먼저 획득하면, DB 시계가 역행하지 않는 한 `iat`가 폐기 시각 이하입니다. 폐기가 먼저 잠그면 이후 발급은 변경된 회원 상태와 인증 버전을 확인합니다. `iat <= 끊은 시각` 규칙상 폐기 직후 같은 초에 새로 발급된 Access도 거절됩니다
- 시각을 DB 한 곳에서 읽어 서버 시계 차이가 비교에 끼어들지 않습니다
- 폐기 작업을 변경과 같은 트랜잭션에 남겨, Redis 기록이 실패해도 사라지지 않고 재처리됩니다

## 다른 안

| 안 | 버린 이유 |
|---|---|
| JPA `@Version`으로 인증 버전 | 인증과 무관한 회원 정보 수정에도 올라가 Refresh가 무효화됨 |
| 커밋 전에 Redis 기록 | 롤백되면 폐기하지 않은 회원의 토큰이 막힘 |
| 앱 서버 시계로 `iat` · 끊은 시각 | 서버 간 시계 차이만큼 순서가 어긋날 수 있음 |
| 폐기 때 Refresh 전부 삭제 | 폐기 직후 새로 로그인해 받은 Refresh까지 지울 수 있음 → 옛 인증 버전만 한 번 삭제 시도 (실패해도 버전 비교로 재발급 거절) |
| 재처리에서 작업을 잡은 채 Redis 호출 | Redis를 기다리는 동안 DB 트랜잭션을 열어 둠 → 임대 후 커밋하고 트랜잭션 밖에서 호출 |
