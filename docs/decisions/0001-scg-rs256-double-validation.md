# 0001. Gateway(SCG) + RS256 이중 검증

> 상태: ✅ 확정 · 결정일 2026-11-02 · 결정한 사람: 사용자 · 팀
> 대체: - · 대체됨: -

## 배경

서비스를 나누면 토큰을 어디서 검증할지 정해야 했습니다. 처음 안은 Gateway만 검증하고 회원 정보를 헤더로 넘기는 방식이었습니다.

## 결정

Spring Cloud Gateway가 RS256 공개키로 1차 검증(블랙리스트 · 회원 단위 폐기 포함)하고, 토큰을 그대로 넘겨 각 서비스가 공개키로 2차 검증합니다. 개인키는 member만 가집니다.

## 고른 이유

포트가 실수로 열려도 위조 요청이 통과하지 않습니다(심층 방어). 공개키만 배포하면 되어 서비스가 서명 키를 갖지 않습니다. 세미의 `JwtAuthenticationFilter`를 키만 바꿔 다시 씁니다.

## 다른 안

| 안 | 버린 이유 |
|---|---|
| Gateway만 검증 + `X-User-*` 헤더 | Gateway를 우회하면 헤더 위조로 통과 |
| HS256 공유 비밀키 | 모든 서비스가 발급 가능한 키를 갖게 됨 |
| JWKS | 공개키가 하나라 환경변수로 충분 |
