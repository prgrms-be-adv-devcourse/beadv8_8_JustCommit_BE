# 타임아웃 · 재시도 · 서킷 브레이커

> 언제 읽나: 외부 호출이나 서비스 간 호출의 실패 처리를 정할 때
> 상태: ✅ 확정 · 마지막 수정 2026-11-04 · 관련: Miro 14, 노션 기획안 「장애 처리」

## 공통값

| 항목 | 값 |
|---|---|
| 라이브러리 | Resilience4j (⬜ Spring Boot 4 호환 버전은 Sprint 1에 확인) |
| 내부 호출 `internal` | 연결 1초 · 응답 3초 |
| 재시도 | 연결 실패 · 503만 최대 3회 (0.2 → 0.4초). 응답 타임아웃 · 4xx는 재시도 안 함 |
| Gateway 기본 | 연결 1초 · 응답 10초, 재시도 없음 (POST 중복 방지) |
| 실패 응답 | 타임아웃 · 서킷 열림 = 503 + `ApiResponse` |

중요도 순서는 타임아웃 → 재시도 제한 → fallback → 서킷 브레이커입니다.

## 호출별 값

| 대상 | 연결 / 응답 | 재시도 | 실패하면 |
|---|---|---|---|
| Gateway → 각 서비스 | 1초 / 10초 | 없음 | 503 + `ApiResponse` |
| Gateway → 충전 승인 | 1초 / 65초 | 없음 | – |
| Gateway → SSE | 타임아웃 끔 | 없음 | – |
| Gateway → 택배 웹훅 | – / 5초 | 없음 | – |
| Gateway → ai 챗봇 | 1초 / 20초 | 없음 | "잠시 후 다시" + 의미 검색 결과만 |
| 내부 REST (기본) | 1초 / 3초 | 연결 실패 · 503만 3회 | 조회는 fallback, 돈 · 상태는 결과 불명 처리 |
| market → product 예약 | 1초 / 3초 (product 처리 상한 2초) | 없음 | 주문 실패, 503. 예약 해제는 즉시 1~2회, 1분 뒤 한 번 더 |
| market → product 해제 | 1초 / 3초 | 성공할 때까지 (요청 안 1~2회, 이후 스케줄러) | fallback 없음 |
| market → product 판매완료 | 1초 / 3초 | 성공할 때까지 (스케줄러) | 주문은 결제완료 유지 |
| market → payment 결제 | 1초 / 3초 | 없음 | 안 간 게 확실하면 해제 후 실패, 타임아웃이면 `PAYMENT_PENDING` 유지 후 조회 |
| member → payment · market (탈퇴 · 계좌 변경 확인) | 1초 / 3초 | 조회라 최대 3회 | Fail-closed: 탈퇴 · 계좌 변경 중단 |
| market → ai 추천 | 🟨 1~2초 | 없음 | 최신 · 인기 상품 |
| product → ai 의미 검색 | 1초 / 1초 | 없음 | 키워드 결과만 |
| product → OpenSearch | 1초 / 2초 | 1회 | "검색 일시 불가", DB 목록 조회는 동작 |
| product → Rekognition · Plant.id (사진 검수) | 3초 / 20초 | 비동기 최대 3회 | 검수 대기 유지, 계속 실패하면 DLT + 관리자 수동 검수 |
| product → Plant.id (품종 자동 추천) | 3초 / 14초 | 2회 (1초 간격) | "직접 선택", 비동기 + 폴링 최대 30초 |
| payment → 토스페이먼츠 | 3초 / 65초 | 연결 실패 · 타임아웃 · 5xx는 결제 조회 후 멱등 키로 1회 | 결과 불명 → 스케줄러 조회 3회 → `REVIEW_REQUIRED` |
| market → 모의 택배사 | 3초 / 5초 | 5분 스케줄러가 같은 `courierOrderNo`로 재예약 | 주문은 결제완료, 접수만 지연 |
| member → Gmail SMTP | 연결 · 응답 · 쓰기 각 5초 | 없음 (사용자가 재발송) | `EMAIL_SEND_FAILED` |

## 서킷 브레이커

| 항목 | 값 |
|---|---|
| 열림 조건 | 최근 10번 중 50% 실패 |
| 다시 시험 | 10초 뒤 3번 |
| 열렸을 때 | 503 + `ApiResponse` |
| 적용 범위 | Gateway → 각 서비스는 필수, 서비스 간 호출은 여력이 있을 때 |
| 확인 | Actuator 서킷 브레이커 엔드포인트, 시나리오 S-J01 · S-J02 |

TimeLimiter는 경로 타임아웃보다 길게 둡니다.

## 결과 불명 처리

응답 타임아웃이 났다고 **바로 보상(되돌리기)하지 않습니다.** 상대가 처리했을 수도 있기 때문입니다.

1. 상태를 "진행 중"(`PAYMENT_PENDING`, 취소중 등)으로 둡니다.
2. 스케줄러가 같은 멱등 키로 다시 요청하거나 결과를 조회합니다.
3. 실제로 실패한 것이 확인될 때만 보상합니다.
