# 서비스 간 REST 규칙

> 언제 읽나: 다른 서비스를 REST로 부르거나 내부 API를 만들 때
> 상태: ✅ 확정 · 마지막 수정 2026-11-08 · 관련: Miro 7 · 22, 노션 기획안 「REST 호출」

## 언제 REST, 언제 이벤트

| 방식 | 쓰는 때 | 예 |
|---|---|---|
| REST (동기) | 결과를 받아야 다음 단계로 갈 수 있을 때 | 상품 예약 · 잔액 차감 · 정산금 지급 |
| Kafka 이벤트 (비동기) | 일어난 일을 알리고, 받는 쪽이 나중에 처리해도 될 때 | 구매 확정 → 정산 · 알림, 회원 변경 → 복제본, 판매 완료 · 예약 해제 · 판매 재개 → product |
| 복제본 | 다른 서비스 데이터를 자주 읽어야 할 때 | 회원 닉네임 · 권한 · 판매자 여부 → `MEMBER_REPLICA`, 판매자 기본 배송지 → market (계좌는 복제하지 않고 내부 API로 조회) |

전체 호출 목록 → [내부 API 목록](../reference/internal-apis.md), 이벤트 → [Kafka 토픽 표](../reference/kafka-topics.md)

## 경로와 보호

| 규칙 | 내용 |
|---|---|
| 경로 | `/internal/v1/...` |
| Gateway | 라우팅하지 않음 (외부에서 부르면 404) |
| 포트 | 서비스 포트는 외부에 열지 않음 → [포트](../reference/ports.md) |
| 인증 | `X-Internal-Key` 헤더 필수. 사용자 `Authorization`도 그대로 전달 (그룹 설정기가 자동으로 붙임) |

## 클라이언트

**HTTP Service Client 그룹**(`@HttpExchange` 인터페이스)으로 만듭니다 (#262 · PR #266 완료). OpenFeign · 디스커버리 서버는 쓰지 않습니다.

| 항목 | 내용 |
|---|---|
| 주소 · 타임아웃 | 그룹(대상 서비스)마다 설정 파일로. 주소는 Docker · K3s 서비스 이름, 서버가 다르면 사설 IP |
| 내부 그룹 (`internal-*`) | `common-web` 그룹 설정기가 `X-Internal-Key` · 사용자 `Authorization` · 연결 실패 1회 재시도를 자동으로 붙임 |
| 외부 그룹 (토스 · 택배사) | 위 헤더 · 재시도를 붙이지 않음 |
| 금지 | `RestClient.builder()`로 직접 만들지 않음 (traceId · 타임아웃 · 내부 키가 빠짐) |
| 병렬 호출 | 서로 결과가 필요 없는 호출은 동시에 보냄 — 탈퇴 확인(market · payment · settlement) |

사용법은 노션 「모노레포 문서」 5절에 있습니다.

## 멱등 키

돈 · 상태를 바꾸는 내부 API는 `Idempotency-Key` 헤더에 **업무 ID**를 넣습니다. **자동으로 붙지 않으므로 호출하는 쪽이 넘깁니다.** 같은 키로 다시 오면 처음 결과를 그대로 돌려줍니다 (예: 결제 `ALREADY_PAID`, 환불 `ALREADY_REFUNDED`).

| 호출 | 멱등 키 |
|---|---|
| 결제 · 상품 예약 | `orderId` |
| 상품 환불 (취소 · 반품) | `orderItemId` |
| 배송비 환불 | `sellerOrderId` |
| 정산 지급 | `settlementId` |

## 에러와 재시도

| 상황 | 처리 |
|---|---|
| 에러 응답 | 내부 API도 `ApiResponse` 형식 |
| 4xx · 503 | 재시도하지 않음 |
| 연결 실패 | 0.2초 쉬고 1번 재시도 |
| 응답 타임아웃 | 재시도하지 않음 → 결과 불명. 결제 · 취소 · 환불은 Saga 복구가 같은 멱등 키로 다시 요청, 상품 예약은 다시 부르지 않고 주문 실패 |

타임아웃 값 → [장애 처리 값](../conventions/resilience.md)
